# 分项规则库

这是一个使用 Git 管理的分项规则与业务认知库，适合长期维护上百个分项。

库内只保存规则、认知、案例、项目注意事项和模板，不保存具体项目的原始成果文件。

## 目录

```text
分项规则库/
├─ docs/
│  ├─ index.md
│  ├─ 分项总表.csv
│  ├─ 00-基础认知/
│  ├─ 01-分项规则/
│  └─ 02-项目注意事项/
├─ templates/
│  ├─ 分项规则模板.md
│  └─ 项目注意事项模板.md
├─ tools/
│  └─ ja_params/              按 JA 编号生成本地参数表
├─ share/
│  ├─ 参数样板.xlsx           全库唯一参数样板
│  └─ ja-params-sample-001/   样例输入，不含参数样板，不含生成结果
├─ CHANGELOG.md
└─ mkdocs.yml
```

## 交安参数

JA-001 至 JA-008 仍是草稿，是否可正式使用看 `docs/分项总表.csv`。要生成参数表时给出三件事：规则库地址（或本机已 clone 的仓库）、一句吩咐、本机必要文件路径。路径每次单独指定，样例目录不是默认位置。`tools/ja_params` 目前只生成 JA-001、JA-002、JA-003。

```text
规则库：https://github.com/Elvis20230520/road-drainage-rule-library
按编号 JA-001 去执行，项目编号 001
本机必要文件路径：D:\资料\某项目
```

多个编号写成「按编号 JA-001、JA-002、JA-003 去执行，项目编号 001」。参数样板全库只有 `share/参数样板.xlsx`，现为九张表，以后只改这一份；指定路径里若有同名文件则先用那一份。该路径下放置台账和 `导线点及水准点.xlsx`，结果写入其中的 `output/`。

执行说明可以二选一，因为有的项目规则和规则库不一致。吩咐里写「用线上文件」，只用规则库里的 `资料参数执行说明-JA-xxx.md`（现放在 `share/ja-params-sample-001/`），不读本机路径中的同名文件。写「用本地文件」，只用本机必要文件路径里的同名执行说明，不读规则库那一份。两句都没写时与现有脚本一致：本机路径里有同名执行说明就用这一份；没有则不读规则库里的执行说明，D/E/F 和 JA-002 的 AD/AE/AF 用脚本内置规则。参数样板不随这两句改变。脚本不读取 `docs/01-分项规则/` 下的分项规则 Markdown，测站和 B 列清洗仍用内置规则。

每个编号按读到的资料参数执行说明填写；没读到文件时按内置规则填。说明要求看图纸时要读图；缺图先列出缺项，不补造数据。JA-001 至 JA-008 现行说明以台账、测点和样板为主。`share/ja-params-sample-001/` 示范 JA-001、JA-002、JA-003 的台账和测点怎么摆，其中的执行说明同时是规则库里的那一份。后五个编号的规则页已写好，样例目录还没有对应台账。说明见 `tools/ja_params/README.md`。

## 最简维护流程

1. 从 `templates/分项规则模板.md` 复制一个新文件。
2. 给分项分配永久编号，例如 `FX-001`。
3. 将文件放入 `docs/01-分项规则/对应分类/`。
4. 在 `docs/分项总表.csv` 增加一行。
5. 规则确认后，把状态从“草稿”改为“正式”。
6. 使用 Git 提交本次修改。

只有状态为“正式”且已到生效日期的规则，才可以直接用于正式任务。

## 编号和文件名

- 分项编号一经发布不得复用，例如 `FX-001`。
- 分项改名时保留原编号。
- 文件名统一为 `编号-分项名称.md`。
- 已停用分项保留文件和历史，不直接删除。

## Git 提交说明

建议提交信息使用以下格式：

```text
新增：FX-001 雨水口布置规则
修订：FX-001 增加低纵坡判断
停用：FX-001 被 FX-105 替代
认知：补充路面排水术语定义
项目：新增项目A注意事项
```

## 本地预览文档站

安装 MkDocs 后运行：

```powershell
mkdocs serve
```

浏览器访问命令输出的网址即可查看带目录和搜索功能的文档站。Git 仓库本身不依赖 MkDocs；没有安装 MkDocs 时，仍可直接阅读和维护 Markdown 文件。
