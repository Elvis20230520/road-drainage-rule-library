# 分项规则库

这是一个使用 Git 管理的分项规则与业务认知库，适合长期维护上百个分项。

库内只保存规则、认知、案例、项目注意事项和模板，不保存具体项目的原始成果文件。

## 目录

```text
分项规则库/
├─ docs/
│  ├─ index.md
│  ├─ 分项总表.csv
│  ├─ 00-基础认知/
│  ├─ 01-分项规则/
│  └─ 02-项目注意事项/
├─ templates/
│  ├─ 分项规则模板.md
│  └─ 项目注意事项模板.md
├─ tools/
│  └─ ja_params/              按 JA 编号生成本地参数表
├─ share/
│  ├─ 参数样板.xlsx           全库唯一参数样板
│  └─ ja-params-sample-001/   样例输入，不含参数样板，不含生成结果
├─ CHANGELOG.md
└─ mkdocs.yml
```

## 参数生成工具

交安 JA-001、JA-002、JA-003 可以在本机按分项编号填参数表。脚本放在规则旁边，方便目录布局相同的项目重跑。规则是否生效，仍看 `docs/分项总表.csv` 里的状态。

```text
pip install -r tools/ja_params/requirements.txt
python -m tools.ja_params run JA-001 JA-002 JA-003 --project 001 --data-dir share/ja-params-sample-001
```

参数样板全库只有 `share/参数样板.xlsx`。工具先找数据目录里的同名文件，没有再用这一份。样例目录不放副本。生成的表写在数据目录的 `output/`，不入库。用法见 `tools/ja_params/README.md`。

## 最简维护流程

1. 从 `templates/分项规则模板.md` 复制一个新文件。
2. 给分项分配永久编号，例如 `FX-001`。
3. 将文件放入 `docs/01-分项规则/对应分类/`。
4. 在 `docs/分项总表.csv` 增加一行。
5. 规则确认后，把状态从“草稿”改为“正式”。
6. 使用 Git 提交本次修改。

只有状态为“正式”且已到生效日期的规则，才可以直接用于正式任务。

## 编号和文件名

- 分项编号一经发布不得复用，例如 `FX-001`。
- 分项改名时保留原编号。
- 文件名统一为 `编号-分项名称.md`。
- 已停用分项保留文件和历史，不直接删除。

## Git 提交说明

建议提交信息使用以下格式：

```text
新增：FX-001 雨水口布置规则
修订：FX-001 增加低纵坡判断
停用：FX-001 被 FX-105 替代
认知：补充路面排水术语定义
项目：新增项目A注意事项
```

## 本地预览文档站

安装 MkDocs 后运行：

```powershell
mkdocs serve
```

浏览器访问命令输出的网址即可查看带目录和搜索功能的文档站。Git 仓库本身不依赖 MkDocs；没有安装 MkDocs 时，仍可直接阅读和维护 Markdown 文件。
